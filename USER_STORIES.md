# Fieldproof — User stories

**Product:** [PRODUCT.md](./PRODUCT.md)


### Funder programme officer

- As a programme officer, I want to see which gates each funded use case has closed and on what evidence, so that disbursement decisions rest on demonstrated readiness rather than on a narrative report.
- As a programme officer, I want use cases where AI is not the binding constraint rejected early, so that grant money is not spent building a model for a problem that policy or incentives would solve.
- As a programme officer, I want a portfolio view of shelfware risk — deployments with no named sustainment owner or with runway ending inside two quarters — so that I can fund continuity before a working model goes dark.
- As a programme officer, I want reach figures labelled with their computation method and population base, so that I can report to my board without overstating what was verified.

### Implementing-organisation delivery lead

- As a delivery lead, I want the evidence each gate requires stated up front, so that my team is not asked for a different bar of proof at every review.
- As a delivery lead, I want to record which roles my deployment depends on and which are unfilled, so that a talent gap becomes a funding conversation instead of a silent failure six months later.
- As a delivery lead, I want a deployment automatically suspended when its data agreement lapses, so that we are never operating a model on data we are no longer permitted to use.

### Data partner steward

- As a data steward at a telecom or satellite operator, I want to grant access in a mode I can defend — aggregate-only, compute-to-data, or emergency-charter release for the duration of a disaster — so that I can support a humanitarian use case without exporting subscriber records.
- As a data steward, I want to see exactly which deployments are relying on my data and for what stated purpose, so that I can revoke access when the purpose changes.

### Model risk and safeguarding reviewer

- As a reviewer, I want validation results broken out by subgroup and by site, so that a model that performs well overall but poorly for a minority group cannot pass on its average.
- As a reviewer, I want to block release where an individual-affecting model has no explainability method or no human check, so that an unappealable automated decision cannot reach a vulnerable person.
- As a reviewer, I want each deployment's risk profile scored across bias, privacy, unsafe use and explainability, so that review effort concentrates where the potential harm is greatest rather than being spread evenly.

### Field operations coordinator

- As a field coordinator, I want to record the real device, connectivity, power and language conditions at my sites, so that a tool assuming smartphones and bandwidth is not scaled into places that have neither.
- As a field coordinator, I want to report a suspected harm or a wrong output in plain language and have it reviewed on a deadline, so that raising a concern does not require me to argue in the language of model performance.
- As a platform administrator, I want every gate decision, exception, data-access term and incident retained and reconstructable for an external evaluator, so that assurance survives staff turnover at both the funder and the implementing partner.
